# PHASE 4 — IMPLEMENT ADVANCED ALERT MANAGEMENT

This is the highest-priority development task.

The current Alerts page is primarily a visualization and derived-status interface.

Turn it into a functional alert management module.

## 4.1 Persistent Alert Status

Implement persistent alert statuses:

- Open.
- Acknowledged.
- Investigating.
- Escalated.
- Resolved.
- Closed.

Requirements:

1. Status changes must be saved on the server.
2. Refreshing the browser must not reset alert status.
3. Restarting the Python server must not reset alert status.
4. Demo and real mode must use the same management implementation.
5. Existing pipeline alerts must retain their original detection information.
6. If an alert disappears from the newest 150 pipeline alerts, its management record must not disappear.

Separate original detection data from analyst-managed metadata.

Suggested model:

```json
{
  "alert_id": "unique-alert-id",
  "management": {
    "status": "Investigating",
    "assigned_to": "SOC Analyst 1",
    "escalated": false,
    "acknowledged_at": null,
    "assigned_at": null,
    "resolved_at": null,
    "notes": [],
    "updated_at": "ISO-8601"
  }
}
```

Use a stable alert identifier.

Do not rely exclusively on array positions or temporary browser indexes.

## 4.2 Analyst Assignment

Implement:
- Assign alert to analyst.
- Change assignment.
- Unassign alert.
- Display assigned analyst.
- Track assignment time.

For the initial implementation, use a configurable local analyst list.

Do not invent real authenticated users.

## 4.3 Alert Investigation Workflow

Implement the following workflow:

```text
New Alert
    |
    v
Open
    |
    v
Acknowledge
    |
    v
Investigating
    |
    +-------> Escalated
    |             |
    |             v
    |        Investigation
    |             |
    +-------------+
                  |
```

Support:
- Acknowledge.

- Add investigation notes.
- Escalate.

- Reopen when appropriate.

For example:
- A closed alert cannot be silently modified as though it were still open.
- Resolving an alert must preserve its investigation history.

## 4.4 Investigation Notes

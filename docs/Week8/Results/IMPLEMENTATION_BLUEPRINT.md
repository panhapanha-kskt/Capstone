# Week 8 implementation blueprint

**DNS Traffic Anomaly Detection · planning snapshot 2026-11-24**

This is an implementation plan, not a claim that the work below has shipped. It translates the [Week 8 audit](../AUDIT_FINDINGS.md) and [interface plan](../WEB_INTERFACE_PLAN.md) into code changes and acceptance evidence. The audit's live checks were on a loopback demo; the model figures come from the promoted [model card](../../../models/MODEL_CARD.md). Recheck the source and evidence at the start of each implementation branch. Two training console files, `dashboard/training-gui/api/main.py` and `dashboard/training-gui/core/jobs.py`, already had local changes during this review; integrate with those changes instead of overwriting them.

## 1. Server identity and workflow controls (P0–P1)

**Touchpoints:** [`dashboard/server.py`](../../../dashboard/server.py) (`_json_body`, `_actor`, `authorize`, `PERMISSIONS`, `triage_action`, `triage_decide`, `_close_case`, `Store._apply_one_inner`, `_alert_action`, `_alerts_bulk`, `_run_request`); [`dashboard/static/js/triage.js`](../../../dashboard/static/js/triage.js) and the shared [`dashboard/static/js/chrome.js`](../../../dashboard/static/js/chrome.js); [`tests/test_dashboard_triage.py`](../../../tests/test_dashboard_triage.py), [`tests/test_dashboard_verdicts.py`](../../../tests/test_dashboard_verdicts.py), [`tests/test_dashboard_soc.py`](../../../tests/test_dashboard_soc.py).

1. Choose an authenticated server-side identity source appropriate to deployment (for example a trusted reverse proxy with a verified user header, or a login/session provider). Reject missing or untrusted identity on protected routes. Resolve analyst ID, tier and operator permission from server-owned records; ignore request-body `actor` for authorization and audit attribution. Keep a separate read-only/demo mode if needed, clearly labeled. Make sessions expire, protect state-changing requests against cross-site submission, and document the trusted proxy boundary. `X-SOC-Request` and host/origin checks remain browser safeguards, not identity.
2. Define one closure policy and call it from **case close**, individual alert `status`/`verdict`, and bulk `close`/`status`/`verdict` paths. Decide explicitly whether all closures require a verdict; the current `WORKFLOW["require_verdict"]` default is false. Enforce required checklist items and the High/Critical false-positive Tier 2 approval rule at the shared write boundary, using the alert's server-known severity and stored case state. Reject or route a direct closure that cannot satisfy the policy. For a bulk request, validate all members before committing so a rejected member cannot leave partial writes. Preserve audit entries for requester, independent approver, decision, affected alert IDs and final label export.
3. **A10 correction:** HTTP bodies cannot currently supply top-level `_approved_by`: `_json_body` strips underscore-prefixed keys before the single-alert and triage handlers. `_alerts_bulk` additionally strips underscore-prefixed nested payload keys. Existing `test_legacy_routes_guardrails` covers this behavior. The internal `_apply_one_inner` helper still treats any truthy `_approved_by` as approval. Replace that implicit trust with a server-verified, pending close-request reference and distinct authenticated approver (or an unforgeable internal approval object), and add a direct helper test plus route regressions. Do **not** describe A10 as a confirmed HTTP approval forgery. Ensure future internal callers cannot fabricate an approval by passing a string.
4. Require an authenticated operator permission in `_run_request` before the rate gate triggers work or writes a successful request audit. Keep the rate limit. In [`dashboard/training-gui/core/settings.py`](../../../dashboard/training-gui/core/settings.py) and [`dashboard/training-gui/api/main.py`](../../../dashboard/training-gui/api/main.py), remove the `ADMIN_TOKEN="admin"` fallback, fail startup or refuse privileged routes when no strong credential/identity is configured, and separate model-admin rights from SOC analyst tiers. Check [`scripts/soc.sh`](../../../scripts/soc.sh) and the training console client for credential provisioning and operator documentation; never put a privileged token in a publicly served page.

**Acceptance tests:** An unauthenticated or spoofed `actor` request cannot gain Tier 2 permissions, and audit identity matches the authenticated principal. A Tier 1 user cannot close a High/Critical false positive through case, single-alert or bulk routes without the same checklist/verdict/approval checks; a distinct Tier 2 user can approve once, and self-approval fails. A request containing `_approved_by` at the top level or inside bulk `payload` does not bypass review. A direct internal helper call with a fabricated approval value fails. Failed bulk validation leaves all members unchanged. `/api/run` denies Tier 1 and unauthenticated users, allows an operator, and still returns rate-limit responses on repeated authorized runs. A missing/default training credential is rejected; an authorized model admin can start and promote according to the existing model gate. Run the three dashboard test modules above and the training console tests after the change.

## 2. Web interface and live walkthrough (P1)

**Touchpoints:** [`dashboard/static/js/chrome.js`](../../../dashboard/static/js/chrome.js) (`pollState`, `pollJSON`), [`dashboard/static/css/shell.css`](../../../dashboard/static/css/shell.css), [`dashboard/static/js/triage.js`](../../../dashboard/static/js/triage.js), and the eight SOC pages in `dashboard/`: [`soc.html`](../../../dashboard/soc.html), [`triage.html`](../../../dashboard/triage.html), [`alerts.html`](../../../dashboard/alerts.html), [`events.html`](../../../dashboard/events.html), [`incidents.html`](../../../dashboard/incidents.html), [`devices.html`](../../../dashboard/devices.html), [`health.html`](../../../dashboard/health.html), [`usecases.html`](../../../dashboard/usecases.html). The classic `/` page and `/training` have separate layouts.

1. Start with the existing shared navigation, mobile menu, Alerts assignment filter and Triage retry state. Extend the shared polling helper to expose loading, last successful update, stale and retry states consistently. Retain last valid data on refresh failure, mark it stale with a timestamp, and clear the warning only after success. Remove silent catches in page-level polling (for example SOC metrics and incident refresh) by sending failures into visible status regions. Treat a `304` as successful freshness confirmation only if a prior response is cached.
2. Inspect the Alerts grid/drawer, Triage listbox and dialogs, Event Explorer, Use Cases controls and incident actions with keyboard and screen reader. Use actual buttons for actions; label tables, inputs and icon controls; announce async results/errors; restore focus after closing drawers/dialogs. Verify the listbox implements the keyboard interaction its ARIA role promises. Apply phone/tablet layouts to all eight routes, including table scrolling and dialog boundaries. Keep shared navigation in `chrome.js` and shared shell rules in `shell.css`.
3. Show API source, generated time and limits next to health/model/event figures. Label `/api/events` as detection-alert events until a raw event store exists, `/api/alerts` as a 150-record feed, and the 120-point run history as restart-limited. Explain that the existing drift report is a stored output with an untrusted baseline (A2); do not present it as current measured traffic drift. Keep simulated incident outcomes conspicuous.
4. Run a real-mode browser walkthrough on `/soc`, `/triage`, `/alerts`, `/events`, `/incidents`, `/devices`, `/health` and `/usecases` with representative Technitium logs. Capture dashboard mode, input source/time range, browser, API responses and screenshots for navigation, filters, polling recovery, case open/close policy and incident/health views. If Elasticsearch/Kibana or other receivers are configured, record delivery evidence separately. A demo fixture check remains useful for UI regression but does not satisfy live ingestion/export acceptance.

**Acceptance tests:** At 390 px, 768 px and desktop widths, each route remains usable without clipped actions. Keyboard-only navigation reaches and operates every primary action; focus returns predictably and error/status text is announced. A forced poll failure shows a stale timestamp and retry while retaining the previous data; recovery clears the warning. Existing dashboard regressions pass, followed by targeted browser checks. A real-mode record names the actual data source; if a service is unavailable, mark only that external check pending.

## 3. Training data, drift and evaluation (P1–P2)

**Touchpoints:** [`scripts/train_models.sh`](../../../scripts/train_models.sh), [`src/dns_detect/monitoring/monitor.py`](../../../src/dns_detect/monitoring/monitor.py), [`src/dns_detect/models/splits.py`](../../../src/dns_detect/models/splits.py), [`src/dns_detect/parsing/dns_parser.py`](../../../src/dns_detect/parsing/dns_parser.py), [`src/dns_detect/models/path_b_predict.py`](../../../src/dns_detect/models/path_b_predict.py), [`src/dns_detect/fusion/stacker.py`](../../../src/dns_detect/fusion/stacker.py), [`scripts/compare_models.py`](../../../scripts/compare_models.py), [`config/success_criteria.yaml`](../../../config/success_criteria.yaml), [`scripts/run_candidate_seeds.sh`](../../../scripts/run_candidate_seeds.sh).

1. **A4 first:** parse mixed timestamp formats consistently in `_time_split` and `load_multifeature_with_meta`, with a clear policy for missing/invalid timestamps and timezone handling. Add mixed fractional/non-fractional fixtures to [`tests/test_splits_strategies.py`](../../../tests/test_splits_strategies.py) and a Path B ordering test. Assert no parseable row silently falls back to source-row order. A changed split manifest invalidates comparisons that assumed the previous partition; record the new hash.
2. **A2:** build a versioned drift baseline from benign **training** rows using the actual model feature contract (Path A features if monitoring that path), with saved distribution bins/counts, sample size and run/split IDs. Make monitor and baseline use identical feature names, transformations and missing-value policy; report coverage and `insufficient_baseline` rather than a retrain recommendation when incompatible. Compare observed counts with saved bins rather than synthesizing a normal sample from mean/std. Keep score saturation and high alert rate descriptive until validated against representative benign and attack traffic. Add tests for identical distributions, shifted distributions, missing features and an attack-heavy input. Do not migrate the promoted metadata in place: generate new metadata in candidate runs, compare behavior, then promote through the gate.
3. **A6:** stage prospective file-registry entries during conversion and merge, then atomically commit to `trained_files_registry.json` only after every required learner, evaluation and run-record step succeeds. A failed run must leave the prior registry intact. Test an injected failure before model completion, rerun `--retrain`, and confirm the inputs are still selected. Review the same transaction boundary for the training console's `new_only` mode.
4. **A5/A7:** specify and implement Path B coverage for full and short client streams in `path_b_predict.py`; document window assignment, padding/masking and `has_score_B` semantics. Because this changes fusion inputs, retrain Path B/fusion and verify train/serve parity. Calibrate the fusion threshold on held-out validation rows separate from fusion fit rows (or evaluate the existing V2 path); keep the frozen test set untouched. In `compare_models.py`, compare candidate and current **fusion** on the same rows and feature context, or explicitly change the gate to Path A until a valid fusion comparison exists. Do not claim a fusion-versus-fusion improvement from the current mixed comparison. Use [`tests/test_path_b_iforest.py`](../../../tests/test_path_b_iforest.py), [`tests/test_thresholds_fusion.py`](../../../tests/test_thresholds_fusion.py) and gate tests for coverage, threshold independence and paired scoring.
5. **A3:** rerun at least three seeds with a common split manifest via `run_candidate_seeds.sh`; report recall, false alarms/benign denominator, FPR and uncertainty per seed, and rule-baseline performance. Keep `success_criteria.yaml` precommitted and record any gate change separately. The promoted card reports 7 false alarms among 1,168 benign queries (0.60% FPR), above the 0.10% target; this is the current release constraint, not a number to erase with a threshold-only retune. Add representative benign and held-out attack-family data before arguing for a new operating point. Promotion requires the documented gate and model-card update.

## 4. Integrations, retention and documentation (P2–P3)

**A13:** [`dashboard/exporters.py`](../../../dashboard/exporters.py), [`dashboard/server.py`](../../../dashboard/server.py) and [`config/soc.yaml`](../../../config/soc.yaml) should expose connector state, delivery attempts and receiver acknowledgements for Elasticsearch, syslog CEF and webhook separately. Keep `SIMULATED`/`NOT_CONFIGURED` labels for incident actions until an external control plane confirms a firewall block or host isolation. Test each connector against a controlled receiver and record its receipt ID/time; a local click is not response evidence.

**A14:** replace the DNS-client approximation in `/api/devices` with an authenticated manager-side agent heartbeat/metric feed, while retaining DNS clients as a separate view. Define agent ID, OS, host, last check-in, CPU, memory, disk and service status with **per-field observation timestamps**. Show unknown and stale distinctly; test Windows, macOS, Ubuntu, disconnected and partial-metric fixtures. No agent integration is implied by current DNS telemetry.

**A15:** define retention, indexing and access policy for raw DNS events, alerts, cases and audit history. Add a durable event/case store and paginated search contract before advertising full Event Explorer history. Verify an event and case can be reconstructed after server restart, that totals reconcile with retained records, and that the current 150-alert feed and 120-point in-memory history are labeled as bounded views until replaced.

**A9:** [`README.md`](../../../README.md) should say the current `train_models.sh` default Path B is Isolation Forest (`PATH_B_TYPE="iforest"`); keep the autoencoder as a documented alternative only where supported.

## Research and framework choice

- **Frontend:** use React 18 already present on Alerts; move the three views to TypeScript with Zod at the API boundary in a subsequent build-system migration. [TypeScript's types are erased at runtime](https://www.typescriptlang.org/docs/handbook/2/basic-types.html), while [Zod `safeParse` validates unknown responses](https://zod.dev/basics). Today's focused code adds runtime guards in the existing JavaScript without a new package or untested build chain. React [Error Boundaries isolate render failures](https://react.dev/reference/react/Component); Alerts now applies them to independent widgets.
- **Backend:** choose Go for the future authenticated SOC API gateway because the priority here is concurrent polling and distributed service resilience. Use `net/http` request limits and timeouts, a server-owned principal and authorization middleware, bounded JSON decoding, consistent response schemas, idempotency keys for writes, and durable audit writes. Run `go test -race`, fuzz input decoders, and `govulncheck`, following [Go's security guidance](https://go.dev/doc/security/best-practices) and [`net/http` server controls](https://pkg.go.dev/net/http#Server). Keep the existing Python detection pipeline behind this gateway until contract tests and dual-run comparisons pass. This is a design choice, not a deployed Go service.
- **Security and motion:** the Python server already returns an enforced nonce based CSP. [MDN describes nonce based `script-src`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src); [OWASP recommends HttpOnly, Secure, SameSite session cookies](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). A real session and authenticated actor remain a separate P0 task. Motion is brief and local, and [reduced motion preferences](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) remove it. The premium treatment does not animate alert counts or imply fresh detections.

## Exactly three implemented improvements

| # | Exact file and observed bug | Implemented change | Acceptance evidence |
|---|---|---|---|
| 1 | `dashboard/events.html`: `load()` had no error handling, so a failed request could leave Loading or old data with no warning; API source names were interpolated into option HTML; the detail close control was a mouse-only span. | Validate the event page response, show loading, updated, stale/offline and retry states, preserve last good results, build source options with DOM APIs, make close a button, label the bounded detection-alert scope, and respect reduced motion. | Headless Chrome populated 100 event rows and displayed Updated; API and page returned HTTP 200. |
| 2 | `dashboard/alerts.html`: a first `/api/state` failure left Connecting indefinitely; a rendering error could remove the page UI. | Validate the feed shape, expose loading/stale/offline/retry status, keep prior data, wrap the two charts and grid in React Error Boundaries, and add a short one-time chart entrance with reduced-motion removal. | Headless Chrome rendered the status, both charts, and grid with demo data. |
| 3 | `dashboard/static/js/triage.js` and `dashboard/triage.html`: queue errors lacked a last good timestamp; pending action buttons were blocked by CSS pointer-events but remained keyboard activatable. | Validate queue shape, show updated/stale/retry text, set native `disabled` on active action buttons during requests, and add restrained queue hover feedback with reduced-motion removal. | Headless Chrome rendered the queue, updated status, and case rows with demo data. |

## Next implementation gate

Introduce a TypeScript build with Zod schemas for `/api/state`, `/api/events`, queue, details, and mutation responses; test malformed payloads and failure/recovery in a browser. The Go gateway must bind actor and tier to an authenticated server-side session; stop trusting the browser's `soc_actor` for permission checks, send session cookies only over HTTPS with `HttpOnly`, `Secure`, and `SameSite`, and preserve the existing CSP and CSRF defenses. Validate request bodies on both the client and server, and reject duplicate write IDs before side effects. Cut over one route at a time after API contract, authorization, concurrency, and real-mode walkthrough tests. This migration is deliberately outside the three focused changes above.

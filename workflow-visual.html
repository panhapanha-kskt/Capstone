DNS Traffic Anomaly Detection — architecture & execution workflows

CADT Capstone · src/dns_detect/ · scripts/ · dashboard/server.py · infra/ — names taken from the code, not the README

The system is a file-based pipeline: Technitium DNS traffic lands as log lines in data/raw/, the core package turns them into features, ML scores and alerts in data/processed/, and two supervised background services (Detector and Learner) keep it running and retrain only through a pass/fail gate. There is no database — every piece of state is a JSON/CSV/JSONL file. The overview comes first; each layer then gets its own focused diagram.

A. Live detection run

scripts/run_pipeline.sh — the same four commands are re-run by dashboard/server.py watch_loop → run_pipeline → pipeline_steps() when a data/raw/*.log changes

sequenceDiagram
  autonumber
  participant W as dashboard/server.py watch_loop
  participant RP as scripts/run_pipeline.sh
  participant LK as utils.pipeline_lock
  participant SC as models.schema
  participant EX as features.extractor
  participant BR as fusion.bridge

  W->>W: log_signature(watch_dir) changed (name, size, mtime)
  W->>LK: detection_running(runs/) — heartbeat runs/.pipeline.readers/#lt;id#gt;
  W->>RP: run_pipeline(zscore, cmd) → pipeline_steps() (same commands)
  RP->>LK: flock -s runs/.pipeline.lock (shared reader lock)
  RP->>SC: python -m dns_detect.models.schema --models-dir models --path-b-model dns_trafficformer
  SC-->>RP: dns_threshold.json features == PATH_A_FEATURES, #lt;name#gt;_norm.json == PATH_B_FEATURES, fusion_lr.json inputs == FUSION_INPUTS
  RP->>EX: python -m dns_detect.features.extractor
  EX->>EX: extract_features_from_multiple_logs(data/raw, *.log) → parse_technitium_log_line per line
  EX->>EX: FEATURES_8 per query + detectors (encoding, random subdomain, NXDOMAIN flood, amplification)
  EX->>FS: export_features_to_json → week3_features_all.json (+ week3_attack_summary.json, week3_suspicious_domains.json)
  RP->>BR: python -m dns_detect.fusion.bridge --week3 week3_features_all.json --output week3_features_with_ml.json --path-b-model dns_trafficformer
  BR->>BR: check_features(raw) — FEATURE_SOURCES, add_window_features (FEATURES_WINDOW), bigram_logprob
  BR->>PA: run_path_a → path_a.score_frame(df)
